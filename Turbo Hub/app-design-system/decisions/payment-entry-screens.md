# Payment entry screens

Implemented Scan QR (Figma 436:65155) and Manager payment notification (436:66403), registered in Overview and linked from Flow References. High-fidelity design contexts and screenshots grounded both screens. Screenshot references are separate preview images; implementation uses the supplied merchant-scene photograph and wallpaper assets, not flattened screen screenshots.

Scanner reuses Status bar, Navigation, Action and Avatar. The camera scene, target frame, side-tool positioning, lower panel and Recent row are page-owned layout. The rounded white lower surface retains the established chrome transition. The source scene crops a wide photographed QR placard and overlays Nykaa Phoenix Mall; implementation follows that composition. Target framing remains visible at the fixed 390 × 844 product geometry. Generic Phosphor lightbulb/image icons and merchant initials replace detailed source branding as allowed by the brief. Existing Action styling remains unchanged. Help, flashlight, image selection and manual-entry actions are no-op placeholders for undefined behavior. No camera, image picker or payment QR decoding runs. The preview’s Next screen link represents the simulated scan’s continuation to the existing Nykaa review. It stays outside product UI.

Manager notification reproduces the source lock-screen layout and request message using Inter and the supplied wallpaper. OS lock-screen framing is a documented exception to blue chrome/light product-content composition. Its wallpaper and clock positioning are page-owned; Chrome backdrop remains one decorative implementation with no new appearance API. A 78px light clock role was added to primitives/semantics and the Foundations recipe with mapped primitive references.

Payment request notification is the new independent navigation control. It owns a native link, app/timestamp header, wrapping plain request text, 12px inset, 4px header-to-copy gap and 8px brand gap. Parent owns wallpaper and placement. It has no notification permission, delivery or timing behavior. No nested interaction units and no appearance variants are added. Hover/focus/active belong to this link. A generic P mark replaces detailed app artwork. Required destination is caller-owned.

The request-pending preview now leads to Manager notification before authorization. The amount query passes through; malformed/out-of-range values fall back to the sample ₹2,500. Browser Enter activation with ₹3,250 opened authorization with the same amount and member/merchant context. Scanner preview navigation opened Nykaa review with its default ₹2,500. Source lock-screen time/date are static sample data.
